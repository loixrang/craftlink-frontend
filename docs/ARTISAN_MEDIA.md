# Artisan portfolio and credential management - FE-ART-003

Completed 2026-09-29. The earlier upload-contract blocker was resolved by the supplied expanded API contract and backend media/credential modules. Read-only inspection confirmed multipart field names and owner credential responses. Frontend and backend contracts have identical text after line-ending normalization; this feature did not edit their content.

The artisan-only /artisan/media route is linked from the dashboard. It loads the owner profile first, guides missing profiles to setup, and provides separate portfolio and credential sections with loading, empty, failure, retry and refresh states. Portfolio reads use the public detail endpoint under a separate list cache key; credential reads use authenticated GET /artisans/me/credentials with a user-scoped cache and runtime validation that strips unknown/private fields. Credential documents are never displayed or cached.

React Hook Form/Zod forms submit exact multipart fields through the shared API client, letting the browser set the boundary. Portfolio sends file/title/description; credentials send file/title/issuer and optional ISO issuedAt. Client checks required fields, lengths, real non-future dates, nonempty files, JPEG/PNG/WebP MIME and the 5 MiB limit. The backend remains authoritative for decoded content, animation and the 25-million-pixel limit. There is no browser-to-Cloudinary integration or frontend secret.

Pending uploads disable inputs and use a synchronous duplicate-submit lock. Failed uploads retain their drafts and selected files; no mutations retry automatically. Uncertain responses advise refreshing before retrying because POST is not idempotent. Cancel the form to refresh its list. Deletion requires inline confirmation and supports cancellation and failure recovery. Successful mutations invalidate the relevant list and public profile. Credential statuses distinguish pending, verified and rejected; rejected credentials can be removed and resubmitted. Portfolio images use HTTPS URLs, suppress referrers and show a fallback on failure. Public image deletion explains the possible CDN delay.
