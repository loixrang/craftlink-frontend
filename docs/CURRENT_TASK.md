# Current Task

Status: COMPLETE
Feature: Nigerian Naira (NGN/₦) currency standardization (no roadmap feature ID; maintenance work outside the roadmap).

Audited every monetary entry, display, validation, schema, type, payload, placeholder and copy path in both repositories. `ArtisanService.priceFrom` is the only monetary field in Craftlink: there are no `minPrice`, `maxPrice`, `minBudget`, `maxBudget`, request/job budgets, artisan hourly rates, fees or payment amounts in either repository, and discovery summaries, dashboards, requests, reviews and admin screens carry no monetary values. Added `src/constants/currency.ts` as the single formatting entry point, wrapping a cached `Intl.NumberFormat` with `style: 'currency'`, `currency: 'NGN'`, locale `en-NG`, `minimumFractionDigits: 0` and `maximumFractionDigits: 2` so `formatCurrency(50000)` is `₦50,000`, whole amounts drop `.00` and stored minor units survive. It accepts an optional currency code and caches formatters per code, so a future currency is a parameter change rather than a component-wide rewrite. The three ambiguous renders (landing page "Starting from", public profile service list, artisan service list, the last of which previously interpolated a raw number with "confirm currency") now use the formatter, and the service editor label/hint and the `priceFrom` validation message state Nigerian Naira. Form values stay numeric strings and `saveService` still sends a JSON number, so no `₦` or separator reaches the API.

Validation: 3 new formatter tests and 2 new public-profile rendering tests; the full 108-test suite, lint, typecheck and the production build pass (pre-existing 595.01 kB chunk warning retained). `Intl.NumberFormat('en-NG', ...)` output was confirmed in Node and through a jsdom render. No desktop browser is attached to this session, so a light/dark mobile-width visual pass was not possible; the only markup changes are text inside existing containers that already use `tabular-nums`. No route, API call, contract, authentication, session, query, mutation, layout or business-logic change, no migration, no database type change, no new dependency, and no stored monetary amount converted, rescaled or moved to kobo. Backend inspection found no currency field, column, parameter or validation anywhere, so NGN is an application-level display assumption; `API_CONTRACT.md` is untouched and remains byte-identical to the backend copy.
