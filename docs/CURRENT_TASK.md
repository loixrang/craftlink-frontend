Feature: Unified artisan profile + profile-photo save (bug fix; no roadmap feature ID; maintenance work outside the roadmap).

The artisan profile setup/edit form previously had two separate save actions: the photo section's "Upload photo" button ("Save profile and upload photo" for new profiles) uploaded the staged file immediately through a separate mutation, while the bottom "Save profile" button only saved profile information and never touched the staged image. The photo section now only stages the image locally (frontend `File` state, existing `profileImageFileError` validation, immediate `URL.createObjectURL` preview, no upload on selection) and the separate upload button is removed; the existing "Remove photo" action is preserved. The single "Save profile" button is now the authoritative save: it validates the form, saves the profile through `PUT /artisans/me` (retaining the current image URL), uploads a staged image through the existing `POST /artisans/me/profile-image` multipart endpoint when one exists, then refreshes the owner, public profile and discovery queries and shows one unified success state. Partial failures are reported honestly ("Profile saved, but the photo could not be uploaded") with the staged image kept for retry; an invalid staged image is rejected before any request, and a failed profile save never triggers an upload. The primary save button represents the complete operation (loading state, disabled controls, existing lock against duplicate submissions/uploads). Backend endpoints, payloads and the Cloudinary integration are unchanged; uploads still go through the backend profile-image route as one multipart `file` part with no manual Content-Type.

Validation: added `src/pages/ArtisanManagementPage.test.tsx` (11 tests) covering local staging without upload, removal of the separate upload action, new/existing profile with and without an image, invalid image rejection, validation-failure blocking, partial upload failure feedback, duplicate-submit protection and remove-photo preservation. The full 119-test suite, lint, typecheck and the production build pass (pre-existing 594.91 kB chunk warning retained). No route, API call, contract, authentication, session, query key, mutation payload, layout or business-logic change beyond the save orchestration; no new dependency.
