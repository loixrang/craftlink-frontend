# Manual location - FE-DISC-003

Discovery filters by administrative area, not coordinates. The location control is a state selector plus a city/LGA selector. The state selector is read-only and lists `SUPPORTED_STATES` from `src/constants/locations.ts`, currently Akwa Ibom only, with an explicit hint that it is the currently supported state. The city selector lists `getLgasForState(selectedState)` and offers an empty "Select city / LGA" option. Changing the city applies immediately, deletes any `page` parameter so the first page of the new result set is shown, and preserves every other filter. Selecting the empty option clears `city` and the `lga` alias but keeps `state`.

The applied location lives in the URL and is the source of truth, so direct links, back/forward navigation and shared links all restore the controls and the result set. `state` defaults to `DEFAULT_STATE`; `city` is read from `city` or, as an alias, from `lga`. A `state` that is not a supported state, or a `city` that is not an LGA of the resolved state, is rejected: the invalid pair is ignored as a whole, the resolved values fall back to defaults, and the results panel shows a visible warning so the reader knows the link could not be honoured.

`readLocation` in `src/schemas/location.ts` performs this resolution and returns both the resolved values and an `invalid` flag that `ArtisanResults` renders. The resolved `state` and optional `city` are spread into `ArtisanFilters` and sent as the `state` and `city` query parameters of `GET /api/v1/artisans`; `state` is always sent, `city` only when one is selected. `lga` never reaches the network. Clearing all filters removes the location parameters along with the rest of the query string.

There is no coordinate entry, radius control, geocoding or address lookup, and none is claimed: the contract defines location filters as state/city plus optional coordinate filters, and this frontend uses only the administrative pair. See the 2026-10-02 entry in DECISIONS.md. The UI does not expose artisan coordinates, does not display a distance for any result, and does not offer distance sorting.

Validation is shared with the rest of discovery: an invalid or incomplete location link is ignored with visible feedback rather than silently returning unrelated results, and the rest of the URL, including keyword, category, rating, experience, availability, sort and page, is preserved.
